# 三份資料來源整合設計指南

> 基於實際檢視的檔案（課程地圖 × 3 種格式、應修科目表 × 2 種複雜度），記錄如何將這三份資料整合進知識圖譜與 RAG 系統。

---

## 一、執行摘要

| 資料來源 | 提取目標 | → Knowledge Graph | → Vector DB |
|---------|---------|------------------|-------------|
| **課程地圖** | 先修關係、學期排列、未來發展 | PREREQUISITE 邊、學期屬性 | 職涯描述文字 |
| **應修科目表** | 必修課程、學分要求、修課規定 | REQUIRES 邊、學分屬性 | 備註規則文字 |
| **學分學程** | 課程清單、學程描述 | INCLUDES 邊（已完成）| 學程描述文字 |

**核心原則**：
- 關係明確、數值清楚 → **Graph**（支援多跳查詢、路徑規劃）
- 敘述性文字、複雜規則 → **Vector**（支援語意搜尋）
- 職涯方向 → **兩者都要**（結構化清單 + 語意搜尋）

## 二、課程地圖

### 2.1 三種實際遇到的格式類型

實際看過 28 份地圖中的三個代表後，發現各系設計方式差異極大：

---

#### Type A：流程箭頭型
**代表**：通訊工程學系.png

```
大一上    大一下    大二上    大二下    大三上  ...
  │          │
電路學I  →電路學II→ 網路理論 → ...
  ↓
電磁學I  →電磁學II
```

- 有明確的學期欄位（大一上/下 ... 大四下）
- 課程框之間有箭頭，代表先後修習順序
- **可提取**：先修關係（高信心）、學期排列
- **適合系所**：工程類（通訊、電機、土木等）

---

#### Type B：資訊圖表型
**代表**：資訊工程學系.jpg

```
基礎課程          專業課程            未來發展
大一/二/三    大四及研究所
─────────    ─────────────    ──────────────────
計算機概論    人工智慧、資料    數位內容產業
資料結構      科學與多媒體      遊戲軟體產業
演算法        研究群            安全監控產業
...           ...               各領域軟體作業分析
```

- **沒有**課程間的箭頭，無法提取先修關係
- 課程依「研究群」分組
- 右側有豐富的「未來發展」職涯方向
- **可提取**：課程研究群分類、職涯清單（最有價值）
- **適合系所**：資工、資管類

---

#### Type C：左右流程型
**代表**：數學系_計算與資料科學組.jpg

```
校訂共同 → 組訂必修基礎 → 組訂必修 → 組訂選修 → 相關專業 → 未來發展
課程          課程            課程        課程        課程       領域
```

- 從左到右代表學習進程（基礎→進階）
- 關係是「群組 → 群組」，非「課程 → 課程」
- **可提取**：學習階段分類、職涯方向
- 先修關係：群組層級、信心度低（⭐⭐）
- **適合系所**：理學院各系

---

### 2.2 「未來發展」區塊為何特別重要

這是整個資料集中**唯一系統性包含職涯資訊**的地方，對高中生問答系統極有價值：

| 系所 | 未來發展內容範例 |
|------|---------------|
| 資訊工程 | 遊戲軟體產業、數位學習產業、資訊安全產業、大型企業軟體... |
| 數學（計算組）| 軟體工程師、系統開發工程師、精算分析師、金融工程分析師... |
| 通訊工程 | （在課程地圖末端的職業欄位）|

回答高中生問題：
- 「讀資工可以做什麼工作？」→ 直接命中
- 「我想當 AI 工程師，要讀哪個系？」→ 反向查詢

### 3.2 pdfplumber 為何不可用

實際提取結果：

```
# pdfplumber 輸出（完全無法使用）
上 下 上 下 上 下 上 下
3 3
0 0 0 0 0
0
3 3
3
...
```

原因：表格使用合併儲存格，pdfplumber 只能讀到數字但失去欄位位置，無法知道「3」對應哪門課的哪個學期。

**結論：全部跳過 pdfplumber，直接送 Vision API。**

### 4.2 PDF 是否值得處理

每個學程的 PDF 包含：
- 學程宗旨與目標（已在 JS 的 `description` 欄位）
- 修課規定（最低學分、選修限制）
- 跨校認定說明

**結論**：PDF 的文字內容複雜且多例外，不適合強行結構化。**直接向量化**。

## 五、Graph vs Vector 完整決策

### 放進 Knowledge Graph 的條件

- 關係明確（A 是 B 的先修、A 系必修 B 課）
- 數值清楚（3 學分、大二上修）
- 需要跨節點推理（學習路徑、修課規劃）

### 放進 Vector DB 的條件

- 自然語言描述（職涯展望、課程目標、學程介紹）
- 規則複雜有例外（備註條件、採計規定）
- 適合語意搜尋（「適合想做 AI 工程師的課程？」）

### 決策表（完整）

| 資料片段 | 具體例子 | 去向 | 理由 |
|---------|---------|------|------|
| 課程地圖先修箭頭 | 電路學I → 電路學II | **Graph** PREREQUISITE | 明確方向關係 |
| 課程地圖學期排列 | 大二上修作業系統 | **Graph** 節點屬性 | 結構化數值 |
| 未來發展職業清單 | 「AI工程師、資料科學家」 | **Graph + Vector** | 結構清單供查詢；語意搜尋 |
| 未來發展描述 | 「本系畢業生具備...能力進入...產業」 | **Vector** | 敘述性文字 |
| 研究群分類 | 「AI、資料科學與多媒體研究群」 | **Graph** Domain 節點 | 已有 IN_DOMAIN 邊 |
| 應修科目表必修課 | 資管系必修微積分 | **Graph** REQUIRES | 明確系所對課程關係 |
| 畢業最低學分 | 128 學分 | **Graph** 節點屬性 | 明確數值 |
| 備註複雜規則 | 「跨課群採計不得重複...」 | **Vector** | 例外規則，LLM 讀文字更好 |
| 院訂/系訂分類 | 「院訂必修」 | **Graph** 邊屬性 | 簡單 enum |
| 學分學程課程清單 | 人工智慧學程包含 CE1001 | **Graph** INCLUDES | 已完成 |
| 學分學程描述 | 「培養跨領域 AI 應用人才...」 | **Vector** | 敘述性文字 |
| 學分學程修課規定 | 「至少修 15 學分...」 | **Vector** | 規則文字 |

## 六、整合後可新增回答的問題

### 原本 RAG 無法回答，整合後可以

| 高中生的問題 | 需要的資料 | 查詢方式 |
|------------|----------|---------|
| 資工系大一要修什麼課？ | 應修科目表 | Graph: REQUIRES + year_level=1 |

| 文學院學士班哲學方向要修什麼？ | 應修科目表 | Graph: REQUIRES + track filter |

## 七、Script 修改需求

### `scripts/parse_requirements_table.py`

1. **移除** `extract_with_pdfplumber()` 函式及相關呼叫
2. **更新** Vision API prompt，加入：
   - `table_type: "single_track" | "multi_track"` 欄位
   - `tracks: []` 欄位（學士班用）
   - 每門課加入 `track` 欄位
   - `rules_text` 收納備註規則文字
3. **加入** `rules_text` 寫入 Vector DB 的邏輯

### `scripts/extract_curriculum_map.py`

1. **更新** prompt，加入 `map_type` 識別（flowchart / infographic / flow）
2. **加入** `career_paths` 欄位提取職涯資訊
3. **加入** `career_paths.description` 寫入 Vector DB 的邏輯

### `scripts/build_knowledge_graph.py`

1. **加入** Career 節點類型
2. **加入** IN_CAREER_PATH 邊
3. **加入** 從 requirements JSON 的 `rules_text` 寫入 Vector DB
